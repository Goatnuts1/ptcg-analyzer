## Access note — read before anything else in this report

**Every live-source fetch this scan attempted was blocked at the network layer.**
`play.limitlesstcg.com`, `limitlesstcg.com`, `pokemon.com`, `en.wikipedia.org`,
`bulbapedia.bulbagarden.net`, `liquipedia.net`, and `pokedata.ovh` all failed identically
— both through the WebFetch tool (`EGRESS_BLOCKED`) and through direct `curl`
(`CONNECT tunnel failed, response 403`, "organization policy"). This is not new to this
session: the parallel weekly-meta-hunt reports from 2026-08-17, 2026-08-24, and
2026-09-14 recorded the exact same blocklist independently. Only GitHub-family domains
and the search backend behind the `WebSearch` tool are reachable from this environment.

That means **step 1 of the skill (pull the live Limitless standings table) could not be
done.** Per this project's own rule ("do not fabricate tournament results, card text, or
win rates; if a source is unreachable, say so"), this report does **not** invent a fresh
share/win-rate table. Where `WebSearch` snippets offered numbers anyway, they are flagged
below as unverifiable and explicitly **not used** — one query this session returned a
runner-up name ("Cobey H.") for the 2026 World Championship final that directly
contradicts the 2026-09-14 report's better-corroborated finding (Diego Cassiraga, cross-
checked across two independent searches carrying matching specific detail — the deck-out
finish, the 2017 finalist callback). This is exactly the kind of self-contradictory
WebSearch noise the prior report warned about; it is not treated as data here.

**Consequence for this scan:** no numeric share/win-rate drift table this cycle (no
trustworthy fresh numbers exist), no new archetype build (the build bar and the build
pipeline both require a real decklist + real card text from a primary source, which
cannot be fetched), and `SHARE_TRENDS` in `src/analysis/futures.py` is carried forward
unmodified rather than rolled forward on invented deltas. What follows is what *can*
honestly be said this cycle.

## The one trustworthy new data point: 2026 World Championships

The only real, well-corroborated event since the last scan is the **2026 Pokémon World
Championships** (Masters Division, San Francisco, Aug 28–30, 797 players) — reported in
detail by the 2026-09-14 weekly-meta-hunt session (which had working access to
`pokemon.com`/PokéRank/Ultimate Guard/PokéBeach that session; access has since gone dark
again). Key facts, carried forward as established:

- Champion **Andrew Hedrick (USA)**, playing **Dragapult ex**, won 13-2, final decided by
  decking out the opponent.
- Runner-up **Diego Cassiraga (Argentina)**, playing **Alakazam / Dudunsparce**.
- **Dragapult-family decks (Dragapult ex + Dusknoir/Blaziken pairings) were ~42% of the
  entire 797-player Masters field.**
- **Top 8: 3 Dragapult-family, 2 Alakazam, 2 Crustle, 1 Ogerpon Box (Teal Mask Ogerpon
  ex).**

**Both archetypes this project actively develops made Worlds Top 8** — `crustle_modern`
(2 of 8) and `ogerpon_box` (1 of 8) — against a field that was 42% the format's best deck.
That is real validation, not a simulated one, for continuing to invest in both. It also
reconfirms last scan's headline from a completely independent angle: this repo's own
Aug-17 mcts2 matrix already had `crustle_modern` as the only 20-candidate deck with zero
losing matchups (floor 53.3%), and the format's best real-world players independently
converged on the same shape two weeks later.

Individual player-to-deck attribution below the Top-8-composition level is **not**
reliable this scan (the 09-14 report already flagged conflicting snippets on this, and
this session's search reconfirmed the pattern with a new contradiction) — only the 3/2/2/1
composition and the two named finalists are reported here.

Granular per-deck Worlds shares (e.g. a claimed "Alakazam 8.99%, Mega Excadrill 4.60%")
surfaced in one `WebSearch` result this session but could not be cross-checked and are
**not reported as fact** — noted only so they aren't mistaken for measured data if they
resurface.

## Calibration caveats (carried forward in full, per CLAUDE.md)

- The mcts2 matrix has a measured ~13pt aggro bias (`mega_excadrill`: sim ~63–65% vs real
  49.51% on thousands of ladder games). Discount `fighting` first.
- `festival_lead` (32.8% mean) and `slowking_annihilape` (32.0% mean) are **pilot
  floors**, not ratings — both contradicted by external evidence (51.18% real WR;
  direct ladder wins over the house deck).
- Cross-turn ISMCTS (`mcts2`) is single-observer; hidden-hand-aware evaluation is not
  built. Treat every number as a floor on true strength, not a ceiling.

## Engineering note (out of scope for this scan, flagged for follow-up)

Rebuilding `data/standard_pool.json` from `src/fetch_standard_pool.py` this scan (needed
to run `--futures`) pulled the current `PokemonTCG/pokemon-tcg-data` `master` branch and
surfaced real drift: several cards several existing tests and decks expect by name —
`Staryu`, `Mega Starmie ex`, `Telepathic Psychic Energy`, `Drilbur (TEF)` — are no longer
present under those names upstream (e.g. `Staryu`/`Mega Starmie ex` now only resolve as
`Misty's Staryu`/`Misty's Starmie`), and the `Drilbur` print-collision resolution picked a
different print (`sv5-85`) than the `pbl-46` some tests expect. This broke roughly 14 of
the ~35 standalone test files on a fresh pool build — unrelated to anything in this
scan's scope (metagame representation, not the data-fetch pipeline), and risky to patch
blind under a scheduled run, so **not touched here**. Root cause: the fetcher pins to
`master` (no commit/tag pin), so a from-scratch rebuild is not reproducible over time as
upstream adds/reorganizes real sets. Flagging as homework for a dedicated engineering
session — this rebuild's pool file was used only for `--futures` (whose rotation-%
numbers cross-checked exactly against the last known `ogerpon_box`/`crustle_modern`
figures, so it's trustworthy for that narrow purpose) and is not being committed as a
"fix" to anything.
