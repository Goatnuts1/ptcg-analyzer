## Registry health — the actual finding this week

Running the full standalone suite (`for f in tests/test_*.py: python3 f`) against a
**freshly generated** `data/standard_pool.json` (this file is gitignored — every fresh
session rebuilds it from `src/fetch_standard_pool.py`, which pulls the live
`PokemonTCG/pokemon-tcg-data` GitHub dump) turned up **18 of 102 test scripts failing**,
none of them touched by any pending code change. Root cause: `fetch_standard_pool.py`'s
dedupe was "first print of a given name wins, across all sets" — true often enough to
be the existing design, but false whenever a name got reprinted with a **different**
Ability/attack kit that a deck registry specifically depends on. As the upstream dump
has grown (more sets ingested since this pool was last spot-checked), newly-added sets
started winning that race away from the print our decks actually need:

| Card | pool had (wrong) | pool needed (right) | broke |
|---|---|---|---|
| Drilbur | sv5-85 "Dig Dig Dig" (Temporal Forces) | me5-46 "Call for Family" (Pitch Black) | `mega_excadrill`, `mega_excadrill_shaymin` |
| Alakazam | sv6-82 "Strange Hacking/Psychic" | me1-56 "Psychic Draw"/"Powerful Hand" | `alakazam_deck`, `chienpao`, `clefairy_stock`/`clefairy_modified` |

Fixed with a small, curated `PRINT_COLLISIONS` table in `fetch_standard_pool.py`
(name + id-prefix → keep-under-a-suffix, or drop in favor of the correct print) — no
behavior changed for any other card; a stray "collision" auto-warning was prototyped
and then deliberately removed, because same-name-different-attacks is the *normal*
case for ordinary reprints in this game (hundreds of vanilla Pokémon do this
harmlessly) and the warning was pure noise.

Separately, three real cards were missing from both the upstream dump and
`data/manual_cards.json` entirely: **Staryu (me3-20)**, **Mega Starmie ex (me3-21)**,
**Telepathic Psychic Energy (me3-88)** — all Perfect Order (mark J), all present in the
raw upstream JSON with `regulationMark: "J"` but `legalities.standard: "Not Legal"` (the
same upstream-metadata-lag already documented for this set's Honedge/Doublade/Aegislash
line in CLAUDE.md — those three got the manual-supplement treatment at the time;
these three needed it too and hadn't gotten it). Added to `data/manual_cards.json` with
their real, verified text pulled directly from the primary-source JSON (not fabricated,
not web-searched) — fixed `greninja`, `starmie_toolbox`, and `slowking_ogerpon` trainer
coverage.

**Suite status after the fix: 99/102 green.** Remaining 3, none touched by the above:
- `test_arena.py`, `test_train.py` — `ModuleNotFoundError: torch` (numpy was missing
  too and has been installed; torch was left uninstalled — it's the optional
  `src/learn/` ML side-module, unrelated to the deterministic engine or this week's
  card-data question, and not worth a large uninspected dependency pull on a scheduled
  run).
- `test_toucannon_deck.py` — "never fired in 40 seeded games: Area Zero Underdepths'
  Bench shrink clause." This is a fully deterministic, seeded assertion (not a flake)
  that was already failing before any change this session and was unaffected by the
  fixes above. It needs the compound sequence "Bench > 5 while a Tera Pokémon is in
  play under Area Zero Underdepths, then the Stadium leaves play" to occur across 40
  greedy-piloted games; both Tera sources in the list (Teal Mask / Wellspring Mask
  Ogerpon ex) resolve to the correct print, so this looks like a genuinely rare
  compound event rather than a data bug — flagging for a maintainer rather than
  guessing at a fix blind.

**Recommendation:** the `PRINT_COLLISIONS` mechanism is curated, not automatic — it
only catches cases someone has gone and checked. Any future "KeyError: card not in DB"
or "StopIteration looking for attack X" on a fresh pool is very likely this same class
of bug (check every Standard-legal print of that name across the upstream dump before
assuming a card is actually missing).

own **Drilbur was silently the wrong print** in every fresh pool build until today's
fix. Any local win-rate numbers anyone ran against a freshly-cloned checkout since this
class of bug appeared would have been testing a Drilbur that does "Call for Family"...
except it wasn't — it was a completely different, ability-bearing Temporal Forces print

`test_metagross_cri_drilbur_pbl.py` now both pass clean against the corrected pool. No
new bad matchups identified (no fresh matrix data this week); the standing two bad
cells from the 2026-08-17 matrix (fighting 15%, grimmsnarl_froslass 46.7%) are
unrefreshed and still the ones to watch.
