to do the routine's normal job.** Read that section first; it's more consequential
than anything in the meta this week.

## 1. THE FINDING: the standalone test suite is not green, and it's not new

Following the skill's own hygiene step, I ran every `tests/test_*.py` as a script
(no pytest in this repo). **16 of 102 files fail**, plus 2 more that fail purely
for environmental reasons (`test_arena.py` / `test_train.py` need `torch` /
`numpy`, which aren't installed here — unrelated to the deterministic engine,
not investigated further). This is not something this scan's actions caused —
`data/standard_pool.json` is gitignored by design and rebuilt fresh by every
session that runs `fetch_standard_pool.py` (per USAGE.md / README.md, exactly
the command this scan ran); rerunning it twice back-to-back reproduced the
identical 1,331-card pool both times. Nobody appears to have run the full suite
since the April 2026 rotation, and it silently drifted red.

**Root cause, confirmed by tracing one failure to the byte:** `fetch_standard_pool.py`'s
manual-supplement merge skips a manual card whenever upstream already has
*any* card with the same bare name — it doesn't check whether it's the *same
print*. `data/manual_cards.json` carries `Drilbur` as `pbl-46` (Pitch Black,
mark J, the print with the Dig Dig Dig attack the `mega_excadrill` archetype is
built on). Upstream's `sv5-85` `Drilbur` (Temporal Forces, mark H, no Dig Dig Dig)
now satisfies the same-name check, so the manual pbl-46 entry gets silently
skipped and the pool's one bare `Drilbur` entry resolves to the wrong print.
Consequences, both confirmed:

- `tests/test_dig_dig_dig.py` and `tests/test_metagross_cri_drilbur_pbl.py` fail
  outright (wrong print, wrong/missing attack).
- The `mega_excadrill` and `mega_excadrill_shaymin` rows in this week's
  `--futures` output (below) **overstate rotation risk** — their 3 copies of
  `Drilbur` are counted as mark H (rotating) when the intended print is mark J
  (safe). I did not hand-correct the number in the futures table; that would
  launder a guess into a data column the same way an unflagged speculative note
  would. The caveat is recorded at the bottom of `docs/FUTURES_2026-08-21.txt`
  instead.

The same failure shape (a bare name resolving to a still-legal print that isn't
the one the deck/effects were written against — almost certainly because the
*intended* print was a mark-G card that rotated out in April and nobody rebuilt
the deck against a still-legal print) is the most likely explanation for three
more failures, though I didn't trace each to the same level of certainty as
Drilbur:
- `tests/test_alakazam.py` — `db.get("Alakazam")` resolves to `sv6-82`, whose
  only attacks are "Strange Hacking" / "Psychic"; the test (and the registered
  effect at `effects.py:1492`, `("Alakazam", "Powerful Hand")`) expects an
  attack named "Powerful Hand" that this print doesn't have.
- `tests/test_chienpao.py`, `tests/test_clefairy.py` — same `StopIteration`
  shape (attack name not found on the resolved print).

Two more failures are a **known, already-documented** gap, not new: `decks.py`
itself has "SUBSTITUTION" comments (lines ~570, ~709, ~740 area) noting
`"Telepathic Psychic Energy"` doesn't resolve in the pool. It's absent from both
upstream and `data/manual_cards.json` entirely. This breaks
`tests/test_gardevoir_real_deck.py`, `tests/test_gardevoir_real_line.py`,
`tests/test_hide_n_sneak_deck.py` — and, more importantly, **it also breaks
`tests/test_ismcts.py` and `tests/test_mcts_keys.py`**, the two tests CLAUDE.md
names as guarding the cross-process determinism invariant and the
"new action kind needs a `_semantic_key` case" rule. Those guards currently
cannot even run.

One archetype looks like checked-in, unfinished work rather than a regression:
`starmie_toolbox` is registered in `DECKS` and needs `Mega Starmie ex` / `Staryu`,
neither of which exists anywhere in the pool or the manual supplement.
`tests/test_starmie.py`, `tests/test_starmie_support.py`, and
`tests/test_greninja_line.py` fail on exactly that `KeyError`. This deck cannot
currently be loaded at all.

Two remaining failures are lower-confidence and I'm not attributing them to the
print-collision bug: `tests/test_mega_excadrill_deck.py` ("Kieran" never fired
in 12 seeded games) and `tests/test_toucannon_deck.py` (Area Zero Underdepths'
bench-shrink clause never fired in 40 games) both read like they could be
seed/sample-size issues on a conditional trigger rather than a card-data bug —
flagging for someone to look at, not diagnosing further here.

**I did not attempt to fix any of this in this scan.** The dedup-logic fix
touches the shared data pipeline every deck depends on, and the rotation-driven
prints need someone to decide the *replacement* card per archetype (not just
patch a lookup) — exactly the kind of unscoped change CLAUDE.md and this
skill warn against making inside a routine run. Recommend a dedicated session:
(1) make `fetch_standard_pool.py`'s manual-merge collision-aware (same name,
different print → keep both, bare name defaults to the manual print per the
project's own print-collision convention), (2) audit `alakazam_deck`,
`test_chienpao.py`'s deck, and `clefairy_stock`/`clefairy_modified` for
rotated-out prints and rebuild against current legal ones or retire them,
(3) either source `Mega Starmie ex`/`Staryu`/`Telepathic Psychic Energy` for
real or pull `starmie_toolbox` from `DECKS` until it can load.

Everything else — 84 of 102 files, including `tests/test_determinism.py` — is
green. The core engine/effect/decode invariants this project depends on for
every number it's ever published are intact; the damage is scoped to the
specific archetypes named above.
