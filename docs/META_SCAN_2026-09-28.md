## 1. Access status — the live meta table could not be fetched

## 3. Proxy-table correction (no fetch needed — found in our own registry)

Last scan (2026-08-20) listed **"Basic Box" as an unrepresentable gap at 1.51%
share.** That was wrong, or at least incomplete: `clefairy_stock` (James Kowalski's
NAIC-2026-winning list, real tournament provenance, already registered) **is** a
Mega Kangaskhan ex / Meowth ex / Lillie's Clefairy ex / Latias ex Basic-Pokémon box —
the same archetype family the community and Limitless call "Basic Box." The
Baltimore-winning list above is a different specific 60 (it runs Raging Bolt ex /
Iron Leaves ex / Enamorus / Iron Crown ex / Teal Mask Ogerpon ex, which
`clefairy_stock` doesn't), so it isn't a byte-for-byte match, but it is the same
archetype shell this repo already tracks under a different label. **Correction: drop
"Basic Box" from the unrepresentable-gap list; map it to `clefairy_stock` /
`clefairy_modified` in the proxy table going forward.** Carry this correction into
next week's scan.

Other previously-noted gaps (Lucario Hariyama, Ogerpon Meganium Hydrapple, Rocket's
Honchkrow, Mega Chandelure, Mega Absol Box) are unconfirmed either way this week — no
new data on them, so they carry forward unchanged from 2026-08-20.

## 5. Critical finding: a print-pinning regression in the card pool, found while
## regenerating data (unrelated to the meta, but urgent)

`data/standard_pool.json` is gitignored and generated fresh per environment via
`src/fetch_standard_pool.py` (upstream `pokemon-tcg-data` dump + `data/
manual_cards.json` supplement, deduped **by card name only**). Regenerating it for
this scan (1,331 cards, up from the 1,300–1,305 documented in `CLAUDE.md`) and then
running the full test suite (`for f in tests/test_*.py; do python3 "$f"; done` — no
pytest in this repo) surfaced **18 of 102 test files failing**, none of which are
mine — no code was changed before this run. Breakdown:

- **2 environment gaps, not real failures**: `test_arena.py` and `test_train.py`
  need `torch`/`numpy`, neither installed in this container. Unrelated to the pool.
- **Confirmed wrong-print collisions (bare-name dedup picked the wrong reprint)**:
  - `"Alakazam"` now resolves to `sv6-82` (attacks: Strange Hacking / Psychic)
    instead of the print carrying **Powerful Hand**, the attack `alakazam_deck`,
    `cynthia_garchomp`'s Chien-Pao interaction test, and `clefairy_stock`'s shared
    fixture all exercise. Breaks `test_alakazam.py`, `test_chienpao.py`,
    `test_clefairy.py`. `"Alakazam"` has no `data/manual_cards.json` entry — this is
    an upstream-vs-upstream collision (multiple real prints share the bare name; set
    processing order picks the loser).
  - `"Drilbur"` now resolves to `sv5-85` (Dig Dig Dig) instead of the pinned
    `pbl-46` (Call for Family) the manual supplement supplies — upstream apparently
    shipped its own bare-named `Drilbur` from an unrelated set, which is processed
    *before* the manual supplement and wins the name-collision silently. Breaks
    `test_dig_dig_dig.py` and `test_metagross_cri_drilbur_pbl.py`. Note this is
    exactly the print-collision situation `CLAUDE.md` already has a documented
    convention for (`"Name (SETCODE)"` suffixing, e.g. `Metagross (CRI)`,
    `Shuppet (PBL)`) — it just hasn't been applied to `Drilbur` yet, because until
    now the bare name was unambiguous.
  - `mega_excadrill_deck`/`toucannon_deck`'s probabilistic checks (`Kieran` /
    `Area Zero Underdepths`' Bench-shrink clause "never fired in N seeded games")
    also failed. Not independently root-caused this session — plausibly downstream
    of the same pool drift shifting AI sequencing, plausibly a pre-existing flake.
    Flagging, not diagnosing further.
- **Cards missing entirely from both upstream and the manual supplement**:
  `"Staryu"`, `"Mega Starmie ex"` (`starmie_toolbox`, `greninja_line`) and
  `"Telepathic Psychic Energy"` (`gardevoir_real`, `hide_n_sneak`, and — because
  `test_ismcts.py`/`test_mcts_keys.py` iterate every registered deck — two generic
  MCTS smoke tests). `data/standard_pool.json` isn't tracked in git, so there's no
  history to diff against; I can't tell from this session whether this is new this
  week or a long-standing gap that simply hadn't been hit before in a from-scratch
  environment. `clefairy_stock`'s own comment already documents working around this
  exact card ("Telepathic Psychic Energy... not yet fetched/implemented —
  substituted with 1 extra Basic Psychic Energy"), which suggests it's the latter.

**I did not touch `effects.py`, `decks.py`, or `manual_cards.json` to fix any of this
this session.** Pinning exact printed IDs for every archetype-critical bare-named
card, and/or adding a fetch-time check that fails loudly when an archetype's
referenced attack/ability text goes missing from its resolved print, is real
engineering work that touches live archetype fidelity across at least three
currently-tracked decks (`alakazam_deck`, `clefairy_stock`, `mega_excadrill`) and
deserves a focused session with review, not a drive-by patch inside an unattended
weekly content scan. Flagging it here as the top priority for the next engineering
session on this repo — **treat any freshly-generated pool's `alakazam_deck`/
`clefairy_stock`/`mega_excadrill` numbers as suspect until this is fixed**, including
this scan's own carried-forward matrix numbers below, which were measured at some
earlier point against a pool snapshot that may or may not have already had this
issue (no way to tell, since the pool file was never version-controlled).
