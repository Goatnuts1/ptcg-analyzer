## CRITICAL engineering finding: a data-layer regression broke 6+ registered
decks, including the flagship `mega_excadrill`

Before measuring anything, this scan ran the full standalone test suite (102
`tests/test_*.py` files, no pytest) per the skill's step-3 discipline. It had
never been run end-to-end against a **freshly rebuilt** `data/standard_pool.json`
in this session (the pool file is gitignored and rebuilt from the upstream
GitHub card dump each session — see `src/fetch_standard_pool.py`). First run:
**18 of 102 failed.**

Two classes, triaged:

**1. Pure data gaps — fixed this session (safe, additive, zero collision risk).**
`Staryu`, `Mega Starmie ex`, and `Telepathic Psychic Energy` (all ME03 "Perfect
Order", regulation mark J) were referenced by `effects.py`'s already-written,
already-tested registry entries (`_jetting_blow`, `_nebula_beam`,
`_telepathic_on_attach`) and by six decks (`starmie_toolbox`, `slowking`,
`slowking_slowbro`, `slowking_annihilape`, `gardevoir_real`, `hide_n_sneak`) —
but were **missing from `data/manual_cards.json` entirely**. `tests/test_starmie.py`'s
own docstring confirms a prior session added them straight to the (gitignored,
non-persistent) pool file and never committed them to the tracked supplement, so
every later pool rebuild silently lost them. Fetched real text for all three,
cross-confirmed against 2+ independent sources each (Bulbapedia, tcgsync listings,
pokeinvesting, and the test files' own inline-quoted expectations, which matched
exactly), and added them properly to `data/manual_cards.json`. Result: **9 of the
18 failures fixed**; `slowking` (a top-5-share real archetype in our own proxy
table) is loadable again.

**2. Upstream print-collision regressions — found, NOT fixed this session (too
risky to blind-fix in an unattended run).** `data/standard_pool.json` is deduped
by bare card name, first-seen-in-upstream-iteration-order wins
(`fetch_standard_pool.py`'s `build_pool`). Two bare names now resolve to the
WRONG print versus what the registered decklists were built and tested against:

- **`"Drilbur"`** now resolves to the upstream Temporal Forces print (`sv5-85`,
  has the "Dig Dig Dig" Ability) instead of the Pitch Black `PBL 46` print
  (`Call for Family` Ability, `Dig Claws` 50 flat) that `mega_excadrill`'s own
  decklist comment says is "the real tournament-list print." This breaks
  `mega_excadrill` AND `mega_excadrill_shaymin` — **our own flagship/baseline
  deck is currently simulating the wrong Drilbur.** (`tests/test_mega_excadrill_deck.py`,
  `tests/test_metagross_cri_drilbur_pbl.py`, `tests/test_dig_dig_dig.py`.)
- **`"Alakazam"`** now resolves to an upstream `sv6-82` print (`Strange
  Hacking`/`Psychic`) instead of the print `alakazam_deck`'s decklist comment
  calls out ("MEG 'Psychic Draw'/'Powerful Hand'"), breaking `alakazam_deck`.
  (`tests/test_alakazam.py`, `tests/test_chienpao.py`, `tests/test_clefairy.py`.)

Both are long-standing (manual_cards.json's last edit predates this scan by
weeks; this just never got caught because the pool hadn't been freshly rebuilt
+ fully tested in one session recently). A correct fix needs the exact correct
print identified and verified against real card text, then `decks.py` AND
`effects.py`'s registry keys updated to the project's own print-collision
convention (`"Name (SETCODE)"`) — a multi-file change that risks silently
changing simulated behavior if gotten wrong, which this project treats as a
serious-severity class of bug. **Recommended as a dedicated follow-up task, not
attempted blind here.**

**Remaining 3 failures are unrelated and pre-existing:** `tests/test_arena.py` /
`tests/test_train.py` fail on missing `torch`/`numpy` (the separate "learning
engine" piece, `docs/LEARNING_ENGINE_PLAN.md` — an environment dependency gap,
not a card-data issue). `tests/test_toucannon_deck.py` fails a seed-dependent
statistical assertion ("Area Zero Underdepths' Bench shrink clause" didn't fire
in 40 seeded games) — looks like pre-existing flakiness in a low-probability
trigger condition, not touched this session.

**Final suite state this scan: 93/102 standalone tests green** (up from 84/102
at the start of the session). `data/manual_cards.json` gained 3 entries (29→32);
no `decks.py`/`effects.py` changes were made — the print-collision bugs are
flagged, not patched.

**Measurement impact: none, by design.** No new games were run this scan (nothing
crossed the build bar), so no fresh matrix numbers were generated with the
still-broken `mega_excadrill`/`mega_excadrill_shaymin`/`alakazam_deck` pool state.
The stoppers table below reuses the existing, unchanged `matrix_2026-08_mcts2.json`
