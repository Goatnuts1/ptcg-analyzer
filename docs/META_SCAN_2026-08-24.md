## What this scan actually found: two data-fidelity bugs in already-registered decks

With the live-meta pull unavailable, this scan's effort went into engine/data health —
still squarely "keep the simulator's representation of the metagame current," since a
deck that's silently playing the wrong cards is a coverage problem no share table would
catch.

### 0. `cli.py` was broken for `--list`, `--round-robin`, `--futures`

A local `from src.engine.decks import DECKS` inside the `--futures` branch of `main()`
shadowed the module-level `DECKS` import for the *entire function* (Python scoping:
one assignment anywhere in a function makes the name local throughout it). Any other
branch that referenced `DECKS` — `--list`, `--round-robin` — hit `UnboundLocalError`
before ever reaching the futures code. Fixed by dropping the redundant local import
(`DECKS` was already imported at module scope). Regression, not present before the
futures-report commit; now covered by the fact that this scan's own `--futures` run
succeeds.

### 1. `data/standard_pool.json` did not exist in this session

Gitignored-by-design (rebuildable via `src/fetch_standard_pool.py`), but genuinely
absent — the first `--list` attempt failed on a missing pool file before even hitting
the bug above. Rebuilt via `python3 src/fetch_standard_pool.py --out
data/standard_pool.json`; this is a local build artifact, nothing to commit.

### 2. Two real print-collision bugs: `Drilbur` and `Alakazam` were silently the wrong card

CLAUDE.md documents the print-collision convention explicitly (suffix the new print,
leave the pool's bare entry alone) and `decks.py`/`effects.py`/several tests already
assumed bare `"Drilbur"` = the PBL 46 tournament print (Call for Family / Dig Claws,
no Ability) and bare `"Alakazam"` = the MEG 56 print (Psychic Draw / Powerful Hand).
Both assumptions were **false in the actual built pool**:

- `fetch_standard_pool.py`'s manual-supplement merge always lets upstream win a
  same-name collision ("if upstream later ships it, the manual entry is dropped" —
  correct when upstream catches up with the *same* card, silently wrong when upstream
  has a *different* card under the same name). Both Drilbur and Alakazam hit this:
  upstream's `sv6-82` "Alakazam" (Strange Hacking / Psychic, no Ability) and `sv5-85`
  "Drilbur" (Dig Dig Dig Ability / Sand Spray) are real, different cards that happen to
  share a name with the manually-added tournament prints.
- Effect code for both correct prints was already fully implemented and tested
  (`_powerful_hand`/`_psychic_draw` in effects.py, `Drilbur (TEF)`'s `_dig_dig_dig`) —
  only the `manual_cards.json` entries were missing/losing the collision. This reads as
  unfinished work from a prior session rather than a new bug: the disambiguation
  comments were already in the code, just not wired into the data layer.
- **`mega_excadrill` is the user's actual played deck** (the house ladder list). It was
  silently running Dig Dig Dig/Sand Spray Drilbur instead of Call for Family/Dig Claws
  for an unknown number of prior sim runs, including whatever measurements fed
  `docs/META_GAUNTLET_2026-08.md`'s real-world calibration study.

**Fix**: added a narrow `_override_bare` opt-in to the fetch script's merge logic (a
manual entry marked this way replaces a same-named upstream entry instead of losing to
it — used only by these two cards) and added `Drilbur (TEF)` / `Telepathic Psychic
Energy` / `Staryu` / `Mega Starmie ex` as the missing manual entries the already-written
effects/tests expected (real text cross-checked via WebSearch against
limitlesstcg/serebii/bulbapedia/tcgplayer, since direct fetch was blocked — see caveat
below). Full standalone suite (`tests/test_*.py` run as scripts): was 17 failing before
this session's fixes, now 3 — the 2 remaining are `test_arena.py`/`test_train.py`
(ML self-play submodule needs `torch`/`numpy`, not installed in this environment,
unrelated to the card/engine layer) and `test_toucannon_deck.py` (one probabilistic
live-fire assertion — "Area Zero Underdepths' Bench shrink clause never fired in 40
seeded games" — confirmed pre-existing, failing identically before any of this
session's changes, unrelated to the cards touched here; not investigated further this
week, flagged for next session).

**Caveat on the new card data**: WebFetch to limitlesstcg/serebii/pkmncards/bulbapedia
was blocked this session (see above), so the 4 new manual entries were built from
WebSearch-summarized snippets cross-checked across 2–4 independent sources each, not a
raw primary-source page read. Recommend a spot-check from a session with broader
network access before trusting them long-term; they already match what the
pre-existing (and presumably-verified-at-the-time) test files assert.

**Spot-check of the fix's actual impact**: re-ran the one recorded matrix cell most
directly exposed to both bugs at once — `alakazam_deck` vs `mega_excadrill`,
`mcts2 @60`, n=60, seed 2026, mirrored (`docs/matrix_2026-08_mcts2.json` has this
pairing at alakazam_deck 24 / mega_excadrill 36 = 60.0%). Post-fix result: **24/36,
bit-for-bit identical.** The corrected cards evidently weren't decisive in this
particular 60-game seeded sample — reassuring for this one cell, but not a re-validation
of the other ~158 cells in that matrix, several of which also involve `mega_excadrill`,
`mega_excadrill_shaymin`, or `alakazam_deck`. Treat those as unverified against the
corrected data until re-measured.

**Side effect on the FUTURE-PROOF report** (`cli.py --futures`): `mega_excadrill`'s
rotation risk drops 26.7%→21.7% (score 71.7→75.2) and `mega_excadrill_shaymin`'s
28.3%→23.3% (score 70.6→74.1), because the real PBL-print Drilbur is mark J, not the
mark-H TEF print that was wrongly in play. `alakazam_deck`'s rotation risk drops
55.0%→50.0% for the same reason (MEG Alakazam is mark I, not mark H). These are
fidelity corrections, not tuning — same category as the Diamond Coat fix CLAUDE.md
already documents (a real gap on an already-pooled card, fixed without moving any
deliberately-tuned number).
