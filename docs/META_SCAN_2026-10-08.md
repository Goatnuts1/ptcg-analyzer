## 6. Engineering/hygiene — the actual substantive work this cycle

With no archetype crossing the build bar, this scan's budget went into **running
the full standalone test suite** (step 3's own prerequisite) and investigating
what it found, since `data/standard_pool.json` is gitignored and gets rebuilt
fresh from the live upstream `pokemon-tcg-data` GitHub dump every session —
nobody had run all 102 `tests/test_*.py` together against a *freshly rebuilt*
pool in a while.

**First full run: 84/102 passed, 18 failed.**

### Fixed this cycle: two silent print-collision regressions, one of them in the house deck

Root cause for 9 of the 18 failures: the fetch script's dedupe rule
(`src/fetch_standard_pool.py`, "first-set-iterated wins, manual supplement only
fills gaps") assumes a manually-added bare card name stays unclaimed by upstream
forever, or that upstream only ever adds the *same* print back. Both
assumptions broke:

- **`Drilbur`.** `data/manual_cards.json`'s bare `"Drilbur"` entry is the real
  Pitch Black 46 print (plain, Call for Family / Dig Claws) that
  `mega_excadrill` — **this project's actual ladder deck** — and
  `mega_excadrill_shaymin` are built around (`decks.py`'s own comment: "Drilbur
  itself is the real PBL 46 print... NOT the ability-bearing 'Drilbur (TEF)'").
  Upstream has since started shipping its own `"Drilbur"` (`sv5-85`, Temporal
  Forces, **Dig Dig Dig** ability) under the identical bare name. The fetch
  script's "now in upstream, skip the manual entry" log line looked healthy but
  was silently swapping `mega_excadrill`'s Drilbur for a different real card
  with a different Ability on every fresh pool build. Confirmed via
  `test_mega_excadrill_deck.py` (was failing — Kieran's gust-for-prizes never
  fired in 12 seeded games) and `test_metagross_cri_drilbur_pbl.py` /
  `test_dig_dig_dig.py` (both pre-existing tests that already encode the
  correct intent and were the ones that caught this).
- **`Alakazam`.** Two real, both currently Standard-legal, prints share the
  English name: `me1-56` (mark I; **Psychic Draw** ability + **Powerful Hand**
  attack — what `effects.py`'s `("Alakazam", "Powerful Hand")` /
  `ABILITY_EFFECTS["Alakazam"]` registrations and `alakazam_deck` are built
  against) and `sv6-82` (mark H, Twilight Masquerade; Strange Hacking/Psychic,
  no Ability). Upstream's set-iteration order processes `sv6` before `me1`, so
  the wrong, ability-less print was silently winning the bare name — breaking
  `alakazam_deck` entirely (`KeyError` cascaded into every test that loads it,
  including `test_ismcts.py` / `test_mcts_keys.py`'s multi-deck sweeps) and
  three standalone attack/ability unit tests
  (`test_alakazam.py`, `test_chienpao.py`, `test_clefairy.py`, all three of
  which independently assert on `Alakazam`'s real "Powerful Hand" text).

**Fix applied** (`src/fetch_standard_pool.py` + `data/manual_cards.json`): a
small, named `UPSTREAM_NAME_COLLISIONS` set now excludes these two names from
the automatic upstream pass entirely; `manual_cards.json` now carries **both**
real prints explicitly under their own names (`Drilbur` / `Drilbur (TEF)`,
`Alakazam` / `Alakazam (TWM)`) — no print is lost, the pool just stops
silently reshuffling which one a deck gets. Both added entries are verbatim
real card data pulled directly from the upstream source for this exact
investigation (not reconstructed from memory, not needing the blocked
limitlesstcg/Bulbapedia access at all, since upstream already serves both
prints — this is a dedupe-ordering bug, not a missing-data gap). Full suite
re-run after the fix: **90/102 pass**, and the 9 fixed files are exactly the 9
predicted by this root cause (verified, not assumed).

**Why this matters beyond "tests are green":** `mega_excadrill` is the deck
actually piloted on ladder (`docs/LADDER_LOG.md`), and this bug meant a fresh
checkout — any new session, any new contributor, any CI run — was silently
simulating the **wrong Drilbur** for it. The futures/rotation report changed
measurably once fixed: `mega_excadrill`'s rotation exposure dropped from 26.7%
to 21.7% (3 fewer miscounted mark-H copies) and `alakazam_deck`'s dropped from
55.0% to 50.0%, in `python3 cli.py --futures`'s own output — concrete, checked
evidence the fix is correct, not just tests going from red to green.

**No recorded matchup number moves.** Neither fix changes any deck's card
*count* or composition — both are "resolve the name to the print the deck was
always documented as wanting" fixes, not content changes, and neither
`"Drilbur (TEF)"` nor `"Alakazam (TWM)"` is referenced by any registered deck
today. The one test that exercises `mega_excadrill`'s real seeded-game behavior
(`test_mega_excadrill_deck.py`) now passes where it previously failed outright
— it was not silently passing-but-wrong before, it was hard-failing, so no
previously-trusted matrix cell needs re-measurement because of this fix.

### Known gaps found, NOT fixed this cycle (real card text needed, source blocked)

Remaining test failures after the fix, cleanly bucketed:

1. **`"Telepathic Psychic Energy"` — a real printed card, absent from the pool.**
   `decks.py`'s own comments already document this for `DECK_CLEFAIRY_STOCK` /
   `DECK_CLEFAIRY_MODIFIED` ("not yet fetched/implemented... substituted with
   Basic Psychic Energy") — but **five other registered decks**
   (`slowking`, `slowking_slowbro`, `slowking_annihilape`, `hide_n_sneak`,
   `gardevoir_real`) reference it directly with no substitution applied,
   failing outright (`test_gardevoir_real_deck.py`, `test_gardevoir_real_line.py`,
   `test_hide_n_sneak_deck.py`, `test_ismcts.py`, `test_mcts_keys.py`). These are
   decks CLAUDE.md describes as "livefire-verified" and fully tested, so this
   gap did not originate this week — it predates this scan and nobody had run
   these files together against a from-scratch pool rebuild recently enough to
   catch it. **Not fixed**, because the only safe fix (apply the same
   documented substitution used in the Clefairy decks) requires knowing
   whether `Telepathic Psychic Energy` has any effect beyond being
   Psychic-typed — guessing would risk silently changing the composition of
   several already-measured, matrix-recorded decks, exactly what CLAUDE.md
   warns against. Needs real card text once limitlesstcg/Bulbapedia access is
   restored.
2. **`"Mega Starmie ex"` / bare `"Staryu"` — missing from the pool entirely.**
   `DECK_STARMIE_TOOLBOX`'s own comment says it was "adapted... to what's
   implemented in this pool," implying both cards resolved at some point in the
   past; they do not now (checked directly — `Misty's Staryu` exists, bare
   `Staryu` does not; no `"Mega Starmie ex"` appears under any Standard-legal
   upstream set at all). Affects `test_starmie.py`, `test_starmie_support.py`,
   `test_greninja_line.py`, `test_slowking_ogerpon_trainers.py`. `starmie_toolbox`
   is not in CLAUDE.md's curated deck narrative and is not part of the live-meta
   proxy table, so this is lower-priority than item 1, but it's the same class
   of gap. **Not fixed** — same real-text blocker.
3. **`test_toucannon_deck.py`** — a probabilistic assertion ("Area Zero
   Underdepths' Bench shrink clause never fired in 40 seeded games"), unrelated
   to the Drilbur/Alakazam fix (toucannon's list uses neither card) and
   unrelated to any card-pool gap. Flagged for next engineering session, out of
   this week's scope.
4. **`test_arena.py`** (`ModuleNotFoundError: torch`) and **`test_train.py`**
   (`ModuleNotFoundError: numpy`, despite `pip3 show numpy` reporting it
   installed — a `pip`/`python3` interpreter mismatch in this container) — both
   environment/dependency gaps in the ML-training side of the repo
   (`src/learn/`), unrelated to card data or the deck registry. Out of scope for
   a weekly meta scan; noted for whoever owns the learning-engine track.

**Net: 90/102 green**, up from 84/102 at the start of this session, with the
two fixes targeting the highest-value gap (the deck actually played on ladder).
The remaining 12 are now precisely characterized rather than an undifferentiated
"18 failures."
